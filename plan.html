Every page on the new site follows these notes. They're based on /minecraft/nbtviewer, the most polished page on the site. References like nbtviewer:1119 point to the line in minecraft/nbtviewer/index.php where the pattern is used.


        

            
⚡ Lightning fastContent is visible and usable in under 1 second on a phone. Nothing blocks the first paint, and everything heavy loads only when it's needed.

            
↔ Reactive layoutsFluid sizing and auto-filling grids. The page works at 320px and at 2560px, with almost no breakpoints.

            
◻ No clutterOne clear job per page. Empty sections are hidden, and details stay behind a click until they're asked for.

            
● Dark themeA single dark palette (#202020 base) shared by every page, with green as the accent.

            
〰 Calm motionShort, smooth transitions only where they explain something: a panel opening, a press, a state change. No decoration.

What the NBT viewer gets right

            

                
PatternHow the viewer does itRule for every page

                
No framework, no build stepVanilla JS in one IIFE, with tiny $ / $$ helpers nbtviewer:435Plain HTML, CSS and JS. Pull in a library only for one specific job (e.g. skinview3d), and only when it's used.

                
Design tokens:root holds --bg --card --card2 --line --text --muted --accent nbtviewer:19Colours exist only as variables in global.css. Pages use the variables and never hard-code hex values.

                
System fontssystem-ui, -apple-system, "Segoe UI", Roboto nbtviewer:37No web-font download. Text appears immediately in the OS font.

                
Fluid sizing--s: clamp(30px, 8.6vw, 46px) sizes every inventory slot. Headings use clamp() too nbtviewer:29, 64Size with clamp() instead of breakpoints wherever possible.

                
Self-filling gridsrepeat(auto-fill, minmax(120px, 1fr)) for tiles, stats and advancements. columns: 3 340px masonry for cards nbtviewer:134, 157Grids decide their own column count. Use masonry for mixed-height cards.

                
Sticky toolbarSearch plus actions stick to the top, with a translucent blurred background nbtviewer:86Tool pages get one sticky toolbar. Content pages don't need one.

                
Jump linksPill links generated only for sections that exist nbtviewer:1045Long pages get a jump-pill row under the title.

                
No empty sectionsStats and advancements cards render only when data exists. A single "+ Add" bar replaces them nbtviewer:1053Never show an empty card or a "nothing here" heading. Hide it, or show one compact prompt.

                
Progressive enhancementA 2D skin image shows instantly, and the 3D library loads from a CDN on first use. If that fails, the 2D image stays nbtviewer:1064–1095Show something useful immediately, then upgrade it. A failed upgrade must never break the page.

                
Pause offscreen workIntersectionObserver stops 3D rendering when the model scrolls out of view nbtviewer:1119Animations, canvases and polling stop when they're not visible.

                
Lazy imagesloading="lazy" decoding="async" on every icon nbtviewer:833Every image below the fold is lazy and has width and height set.

                
Graceful image fallbackOne capture-phase error listener: API render → local texture → missing-texture pattern nbtviewer:836Broken images get a sensible fallback, never a broken-image icon.

                
Lazy renderingTree nodes build only when opened, 250 at a time with "Show more". "Expand all" stops at 3 levels nbtviewer:1551Never render thousands of rows up front. Build on demand and in chunks.

                
Cheap searchAn 80ms debounce, then toggle a .hit class to dim non-matches instead of re-rendering. Raw search is capped at 300 results nbtviewer:1706, 2086Filters toggle classes on existing elements. Cap result counts.

                
Event delegationOne document click listener routes on data-act, data-copy and similar attributes nbtviewer:1981Avoid per-element listeners and inline onclick.

                
Details in a drawerClicking an item opens a side drawer with breadcrumbs for nested containers. Hover shows a light tooltip nbtviewer:1640The main view stays scannable. Depth lives in a drawer, dialog or <details>.

                
Native dialogs<dialog>.showModal() for share and resource packs nbtviewer:1887Use the browser's dialog (free focus trap, Esc and backdrop), not custom modals.

                
Keyboard/ focuses search. Esc closes the innermost layer first. [ ] switch players. Arrow keys walk slots nbtviewer:2088Every tool page supports / and layered Esc.

                
Instant feedbackA "Copied!" swap for 1s, buttons disabled while loading, toasts that disappear on their own nbtviewer:2019, 1740Every action responds within 100ms, even if it only says "working…".

                
Server-side cachingapi.php: renders cached on disk, immutable 30-day headers, misses re-checked after a day, session lock released so images load in parallel api.php:57–110Every PHP endpoint that calls an external API caches its result and sends real cache headers.

                
Privacy by defaultFiles are parsed in the browser and only uploaded when you press Share. The API key stays server-sideDo the work client-side where possible. Keys never reach the browser.

Rules

            
    
                
  • Three surface levels, no more: page (--bg), card (--card), and inset rows inside cards (--card2). Depth comes from these steps, not from shadows.
    • 
                
  • Green means "act" or "done": primary buttons, focus rings, progress, active tabs. Never use it for decoration.
    • 
                
  • Status colours are tinted backgrounds with a matching border (#2d4a24 + #4f8a3a for green), never bright fills. They're used in badges, toasts and states.
    • 
                
  • A section may re-tint --accent (e.g. Steam blue, Books warm gold), but surfaces and text stay the same everywhere.
    • 
                
  • Set color-scheme: dark so scrollbars, form controls and date pickers render dark too.
    • 
                
  • Contrast: --muted on --card is about 5.2:1, which passes WCAG AA. Never put text darker than --muted on any surface.
    •

Reactive layout

            

                
Do
    
                    
  • Mobile first. Start at 320px wide and let the layout grow.
    • 
                    
  • auto-fill / minmax() grids, flex-wrap toolbars, and columns masonry.
    • 
                    
  • clamp() for font sizes and repeated UI sizes (like the viewer's --s).
    • 
                    
  • min-width: 0 on flex and grid children, and ellipsis on long names.
    • 
                    
  • Only add a breakpoint where content actually breaks (the viewer needs just 3: 560px hero, 520px crafting grid, header).
    • 
                    
  • Panels like the drawer use width: min(460px, 100vw), so they're full-screen on phones automatically.
    • 
                    
  • Tap targets are at least 40px on touch.
    • 
                

                
Don't
    
                    
  • Scroll the page sideways. Only code and tree blocks may scroll horizontally.
    • 
                    
  • Use fixed pixel widths on containers.
    • 
                    
  • Use separate mobile and desktop markup or images (the homepage currently picks a different slideshow by user agent). Use CSS and srcset instead.
    • 
                    
  • Rely on hover for anything essential. Hover only adds polish.
    • 
                    
  • Use body { overflow: hidden } (the homepage does).
    •

Rules

            
    
                
  • Server-render the first view in PHP. JS enhances the page and isn't needed to see content. The data-driven header is rendered in PHP, not fetched (plain HTML pages are the only exception).
    • 
                
  • Defer every script (defer or end of body). Load libraries on first use, like loadSkinLib() nbtviewer:1064.
    • 
                
  • Images: WebP (or AVIF) with width, height, loading="lazy" and decoding="async" below the fold. Galleries show generated thumbnails (≈400px) and open the full image on click.
    • 
                
  • Cache everything static for a year with versioned URLs (global.css?v=3). The .htaccess rule: Cache-Control: public, max-age=31536000, immutable for /assets and /media.
    • 
                
  • API pages cache server-side to disk, like api.php. Steam, Hypixel, Retro and Google Books responses get a cache file with a sensible lifetime (5 min to 1 day).
    • 
                
  • Close the PHP session early (session_write_close()) on endpoints that can be hit in parallel api.php:16.
    • 
                
  • Render lists in chunks (about 250 at a time) and build hidden content only when it's opened.
    • 
                
  • preconnect to any external host a page needs straight away (the viewer does this for crafthead.net).
    • 
                
  • Use content-visibility: auto on long below-the-fold sections (stats, raw data) so the browser skips laying them out until they're near the screen.
    •

Do
    
                    
  • Animate only transform and opacity (plus colour on hover).
    • 
                    
  • Keep it under 200ms. Anything longer feels slow on a fast site.
    • 
                    
  • Use ease-out for things entering. Exits can be instant.
    • 
                    
  • Respect prefers-reduced-motion: turn off loops, spins and smooth scroll.
    • 
                    
  • Stop loops when they're offscreen (IntersectionObserver).
    • 
                

                
Don't
    
                    
  • Use page-load or entrance animations (fade-in on scroll, staggered cards).
    • 
                    
  • Animate width, height, top or margin.
    • 
                    
  • Use transition: all (current global.css uses it 4 times).
    • 
                    
  • Use slow 0.5s transitions, like the current mobile nav and input hover.
    • 
                    
  • Flash colours on hover (the current button:hover { background: lime }).
    • 
                

            

        


        

            
No unnecessary clutter

            
    
                
  • One job per page and one primary (green) button per view. Everything else is a secondary button or a link.
    • 
                
  • Progressive disclosure: overview first, details on click (drawer, <details>, "Show all 312 recipes" nbtviewer:1434), raw data last.
    • 
                
  • Hide what's empty. No empty cards, no "0 results" headings, no placeholder sections.
    • 
                
  • Muted secondary text instead of extra headings or boxes. Help text is one line, muted, under the title.
    • 
                
  • No decoration for its own sake: no gradients, glows, borders inside borders, or shadows on cards.
    • 
                
  • Nothing plays or flashes on load: no autoplay media, no popups. The epilepsy-warning page keeps its warning gate.
    • 
                
  • Toasts disappear on their own (about 9s for errors, shorter for confirmations), stack in one place and never block content.
    • 
                
  • Remove debug output (the homepage logs console.log("Mobile")).
    • 
                
  • The footer stays light: section links, Sitemap, and one line of copyright. The cat fact can stay, but it loads after the page is idle.
    •

Accessibility basics

            
    
                
  • Visible :focus-visible ring in --accent on everything clickable. Never remove an outline without a replacement.
    • 
                
  • Real <button> elements for actions and <a> for navigation (not clickable divs).
    • 
                
  • aria-hidden or aria-expanded on drawers and menus (the viewer already does this nbtviewer:1678). role="option" in custom pickers.
    • 
                
  • Every image has alt (empty if decorative). Every input has a label.
    • 
                
  • Full keyboard use: Tab through everything, Esc closes, Enter activates.
    • 
                
  • One <h1> per page, with headings in order.
    • 
            

        


        

            
Lessons from the viewer things not to repeat

            
    
                
  • It spends about 10 lines undoing global.css (:where(...) button { padding:0; background:none… }, !important on the picker, and margin:auto on dialogs because global zeroes every margin) nbtviewer:42–47, 361. Fix: the new global.css must not style bare button, input, label, table or * margins. Components are opt-in classes.
    • 
                
  • Lots of inline style="" in templates (dialogs, drawer headings, flag icons). Fix: give them small classes.
    • 
                
  • Glint and the idle spin ignore reduced-motion. Fix: add a prefers-reduced-motion block.
    • 
                
  • Hard-coded /minecraft/items_1.21.11/ paths (4 places), which break once that duplicate folder is deleted. Fix: use one ITEMS_BASE constant pointing at /minecraft/tools/item-list/.
    • 
                
  • The 34 MB merged_resource_pack.zip and example JSONs sit in the web root. Keep only the example the "Try an example" button uses. Move the rest to _dev/.
    • 
                
  • 160 KB in one file is fine for a tool, but the shared parts (buttons, cards, badges, drawer, dialog, toast, tree) belong in components/ so other pages get them for free and the browser caches them.
    • 
                
  • Some greys are hard-coded (#3a3a3a, #474747, #555). Fix: map them to tokens (--btn2, --btn2-hover, --line-strong).
    •
